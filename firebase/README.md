# firebase/ — canonical Firebase config

These two files are the **source of truth** for Firebase on this project.
They are downloaded from the Firebase console (project `koinikeyview`) and are
NOT secrets — Google ships them inside every app binary. They are safe in a
public repo.

| File | Belongs at build time in | For |
|---|---|---|
| `google-services.json` | `android/app/google-services.json` | Android FCM |
| `GoogleService-Info.plist` | `ios/Runner/GoogleService-Info.plist` | iOS APNs via FCM |

They live here rather than in `android/` and `ios/` because CI regenerates
those directories with `flutter create` on every run, which would wipe them.
`.github/workflows/ci.yml` copies them into place after each `flutter create`.

Both are for bundle id / package name **io.koini.keyview**, Firebase project
**koinikeyview** (project number 292723856032).

## ⚠️ One manual step remains for Android push

`firebase_core` on Android needs the **google-services Gradle plugin** applied,
which `flutter create` does not add. Until that is done, an Android build
succeeds but `Firebase.initializeApp()` throws at runtime — `PushPlatform`
catches it and quietly disables push, so nothing crashes and nothing arrives.

The durable fix is the one this repo's `.gitignore` already anticipates:

> `# platform dirs are generated by 'flutter create .' and ARE committed once generated`

Generate `android/` and `ios/` once locally, add the Gradle plugin, commit both
directories, and drop the `flutter create` steps from CI. After that the config
files can move to their real homes and this folder becomes a backup copy.

iOS additionally needs the Push Notifications capability and a Background Modes
→ Remote notifications entry in Xcode. The App ID already has the capability
enabled on the Apple side (Team WW8T4Y4422).
